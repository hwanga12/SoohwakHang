# 🌱 특화 프로젝트 트러블 슈팅 요약 (발표/PPT용)

팀원들이 이해하기 쉽도록 프로젝트 진행 중 발생했던 주요 기술적 문제와 해결 과정을 간략하게 정리했습니다.

---

### 1. 📂 빌드 폴더가 안 보여요! (VS Code 탐색기 설정)
*   **문제 상황:** 빌드 결과물(`build`, `install`)이나 로그(`log`) 폴더가 `.gitignore`에 등록되어 있어 탐색기에서 보이지 않아 협업 시 혼란 발생.
*   **해결 방법:** VS Code 설정(`settings.json`)을 수정하여 무시된 파일도 탐색기에 표시되도록 복구하여 팀원 모두가 빌드 상태를 쉽게 확인할 수 있게 함.

### 2. 🛑 시뮬레이션 종료 후에도 프로세스가 남아요 (Ctrl+C 종료 로직)
*   **문제 상황:** Gazebo나 Nav2 시뮬레이션을 껐는데도 실제 프로세스가 배경에 남아 있어, 다시 실행할 때 오류가 발생함.
*   **해결 방법:** 종료 스크립트를 보강하여 시뮬레이션과 관련된 모든 '자식 프로세스'를 안전하고 확실하게 찾아내어 정리하도록 개선함.

### 3. 🤖 로봇이 자꾸 식물에 부딪혀요 (이동/수확 좌표 분리)
*   **문제 상황:** 지도에서 식물을 누르면 로봇이 너무 가깝게 붙어서 다음 이동 시 장애물 경고가 뜨거나 끼이는 현상 발생.
*   **해결 방법:** '일반 관측용 위치'와 '실제 수확용 위치'를 분리함. 평소에는 안전한 통로 중앙에서 멈추고, 수확할 때만 작물 쪽으로 접근하도록 로직을 나눔.

### 4. 🍅 토마토가 왜 하얀색이죠? (3D 모델 렌더링)
*   **문제 상황:** 특정 그래픽 환경(Ogre2)에서 토마토가 빨간색이 아닌 흰색으로 출력되어 시각적 몰입감이 떨어짐.
*   **해결 방법:** 재질 정보가 분리된 OBJ 방식 대신, 색상과 재질이 하나로 통합된 GLB 포맷으로 모델을 교체하여 어떤 환경에서도 빨갛게 보이도록 해결함.

### 5. 🗺️ 식물을 눌렀는데 반대 방향으로 가요 (2단계 경로 계획)
*   **문제 상황:** 현재 위치를 고려하지 않고 고정된 한쪽 목표만 쓰다 보니, 바로 옆 식물을 두고도 통로를 크게 한 바퀴 돌아가는 비효율 발생.
*   **해결 방법:** '통로 진입점' -> '최종 관측점'의 2단계 이동 구조를 도입함. 로봇이 현재 어디 있는지 계산해서 가장 가까운 통로 입구부터 찾아 들어가도록 똑똑하게 바꿈.

### 6. 🏁 다 왔는데 자꾸 실패라고 떠요 (도착 판정 완화)
*   **문제 상황:** 로봇이 식물 앞까지 거의 다 왔는데, 울타리와 너무 가깝다는 이유로 마지막 몇 cm를 못 가고 '실패' 처리됨.
*   **해결 방법:** 목표 지점 근처(약 55cm 이내)까지 도달했다면 장애물 때문에 완전히 겹치지 못하더라도 '도착 성공'으로 간주하는 완충 로직을 추가함.

### 7. 🏗️ 로봇팔 갈고리가 뒤를 보고 있어요 (메쉬 회전 보정)
*   **문제 상황:** 로봇팔의 물리적인 충돌 영역은 앞을 향해 있는데, 눈에 보이는 3D 모양만 뒤를 보고 있어 수확 장면이 어색함.
*   **해결 방법:** 3D 모델의 시각적 회전값(Yaw)을 180도 보정하여, 실제 동작 방향과 눈에 보이는 갈고리 방향을 일치시킴.

### 8. 📍 로봇 위치가 갑자기 튀어요 (좌표계 동기화)
*   **문제 상황:** 시뮬레이션 시작 시 사용하는 임시 좌표계와 실제 위치 추정 시스템(AMCL)이 서로 충돌하여 로봇 위치가 엇갈리거나 명령이 안 먹힘.
*   **해결 방법:** 시스템이 안정화되면 임시 좌표계를 자동으로 끄고 AMCL이 주도권을 잡도록 순서를 정리하여 좌표계 간의 간섭을 제거함.

### 9. 🔄 로봇팔이 거꾸로 달려 있어요 (상하 반전 보정)
*   **문제 상황:** 로봇 머리 위에 달린 로봇팔의 모델링 방향이 상하가 뒤집혀 있어, 실제 작동 방향과 시각적인 모습이 일치하지 않음.
*   **해결 방법:** 로봇팔 모델링에 X축 대칭(상하 반전)을 적용하고, 이에 맞춰 충돌 영역과 관절 위치를 재조정하여 머리 위에서 정상적으로 작동하도록 수정함.

## 🏎️ AgriBot의 똑똑한 주행 알고리즘 (어떻게 목적지까지 가나요?)

로봇이 목적지를 전달받았을 때, 단순히 일직선으로 달리는 것이 아니라 아래와 같이 **'안전한 경로를 잘게 쪼개어'** 이동합니다.

1.  **목표 입력 (사용자 클릭)**: 사용자가 지도에서 특정 식물을 선택합니다.
2.  **안전 경로 판단 (Safe Route Planning)**: 로봇은 식물까지 직선으로 가지 않습니다. 미리 정의된 **'순찰용 안전 지도'**를 보고, 어느 통로를 거쳐야 가장 안전하고 빠른지 먼저 계산합니다.
3.  **단계별 이동 (2-Step Navigation)**: 목적지까지의 경로를 크게 두 단계로 나눕니다.
    *   **1단계 (통로 진입)**: 먼저 식물이 있는 통로 중앙의 안전한 지점(**Anchor**)까지 이동합니다. 이 과정에서 다른 통로에 있더라도 안전하게 회전하며 통로로 진입합니다.
    *   **2단계 (정밀 접근)**: 통로 중앙에 안착한 후, 식물을 가장 잘 볼 수 있는 최종 관측 지점(**Final Pose**)까지 짧게 전진하여 멈춥니다.
4.  **실시간 회피 및 주행**: Nav2(주행 프레임워크)가 로봇의 눈(LiDAR/Camera)을 통해 실시간으로 장애물을 감지하며, 쪼개진 목적지들 사이를 부드럽게 연결하며 주행합니다.

**💡 요약하자면:** 목적지까지 한 번에 무작정 가는 것이 아니라, **"먼저 안전한 통로 중앙까지 가고, 그 다음 식물 앞으로 붙는"** 징검다리 방식을 사용하여 주행의 안정성을 극대화했습니다.

# AgriBot Gazebo/RViz 실행 명령

이 문서는 저장소 루트를 자동으로 찾는 방식으로 정리되어 있습니다. 팀원마다 clone 위치가 달라도, `S14P21A602` 저장소 안에서 실행하면 같은 명령을 그대로 사용할 수 있습니다.

## 1. 공통 환경 변수

아래 명령은 각 터미널에서 먼저 실행합니다. 현재 셸이 `S14P21A602` 저장소 내부 아무 위치에만 있어도 됩니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
```

## 2. 최초 1회 또는 소스 변경 후 빌드

정적 맵을 다시 만들고, 현재 통합 런치가 실제로 참조하는 패키지까지 함께 빌드합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"

python3 src/agribot_navigation/agribot_navigation/generate_static_map.py \
  --output-prefix src/agribot_navigation/maps/farm_map \
  --boundary-yaml src/agribot_navigation/maps/farm_exploration_boundary.yaml

colcon build --packages-select \
  agribot_interfaces \
  agribot_description \
  agribot_navigation \
  agribot_iot \
  agribot_bringup \
  --symlink-install
source install/setup.bash
```

이전 Gazebo/Nav2/RViz/IoT 세션이 남아 있으면 먼저 정리합니다.


## 4. 권장 실행 방식

현재 기본 실행은 터미널 1개에서 Gazebo + robot spawn + Nav2 + RViz를 함께 띄우고, 터미널 2에서 patrol 시작만 보내는 방식입니다.

### 그래픽 프로필 선택 기준

- 기본값은 `system` 입니다. 저장소 코드가 `DRI_PRIME=1`, `__NV_PRIME_RENDER_OFFLOAD=1` 같은 외장 GPU 강제 환경변수를 넣지 않고, 현재 우분투 세션의 기본 그래픽 경로를 그대로 따릅니다.
- 안정성이 가장 중요할 때는 아래처럼 명시적으로 `system` 을 주면 됩니다.
- 외장 GPU 강제 사용이 꼭 필요할 때만 `AGRIBOT_GRAPHICS_PROFILE=nvidia` 를 앞에 붙여 실행합니다. 이 경우 Gazebo/RViz가 RTX 4070 쪽으로 오프로딩될 수 있지만, 머신과 드라이버 조합에 따라 종료 안정성이 떨어질 수 있습니다.

예시:

```bash
AGRIBOT_GRAPHICS_PROFILE=system ros2 launch agribot_bringup simulation.launch.py use_iot:=false
AGRIBOT_GRAPHICS_PROFILE=nvidia ros2 launch agribot_bringup simulation.launch.py use_iot:=false
```

### 터미널 1: Gazebo + Nav2 + RViz 통합 실행

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

AGRIBOT_GRAPHICS_PROFILE=system \
ros2 launch agribot_bringup simulation.launch.py \
  use_iot:=false
```

설명:
- 이 명령 하나로 Gazebo, robot spawn, Nav2, RViz가 함께 뜹니다.
- 현재 `simulation.launch.py`는 내부에서 `navigation.launch.py`를 `use_rviz:=true`, `patrol_robot_pose_topic:=/odom`으로 포함합니다.
- `use_iot:=false`를 줘서 기존 분리 실행과 최대한 같은 경로로 띄웁니다.

### 터미널 2: Patrol 시작

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/start std_srvs/srv/Trigger "{}"
```

Navigation lifecycle 이 모두 active 가 된 뒤 실행합니다. 보통 RViz가 뜬 뒤 5~10초 정도 기다리면 됩니다.

정상 응답 예시:

```text
success=True
message='Patrol start requested from the first waypoint.'
```

## 5. 다른 실행 방식

### 5-1. 문제 분리를 위한 저부하 분리 실행

Gazebo 와 Nav2/RViz 를 분리해서 올리고 싶을 때 사용하는 방식입니다. 통합 실행에서 문제가 생겼을 때 원인 분리에 유리합니다.

터미널 1:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

AGRIBOT_GRAPHICS_PROFILE=system \
ros2 launch agribot_description spawn_agribot.launch.py \
  publish_map_to_odom_tf:=false \
  use_camera_bridges:=false
```

터미널 2:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"

source install/setup.bash

AGRIBOT_GRAPHICS_PROFILE=system \
ros2 launch agribot_navigation navigation.launch.py \
  use_sim_time:=true \
  use_rviz:=true \
  patrol_robot_pose_topic:=/odom
```

터미널 3:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
```

### 5-3. Patrol 자동 시작

Navigation 이 뜨자마자 patrol 이 자동으로 시작되게 할 수 있습니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"

AGRIBOT_GRAPHICS_PROFILE=system \

  use_sim_time:=true \
  use_rviz:=true \
  patrol_robot_pose_topic:=/odom \
  patrol_autostart:=true
```

### 5-4. Nav2 만 실행하고 patrol 노드는 빼기

수동 goal 테스트나 Nav2 자체만 확인할 때 사용합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_navigation navigation.launch.py \
  use_sim_time:=true \
  use_rviz:=true \
  use_patrol:=false
```

### 5-5. Patrol 중지 / 재개

patrol 이 이미 실행 중일 때 수동으로 멈추거나 다시 이어갈 수 있습니다.

중지:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/stop std_srvs/srv/Trigger "{}"
```

재개:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/resume std_srvs/srv/Trigger "{}"
```

### 5-6. 수동 harvest 요청

`navigation.launch.py` 에서 `use_harvest_route:=true` 가 기본이라, harvest coordinator 가 함께 떠 있으면 토마토 ID 를 직접 보내 수확 접근 시퀀스를 시작할 수 있습니다.

예시 tomato ID 는 `crop_instances.yaml` 기준으로 `farm01_plant_01_tomato_01` 형식입니다.

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic pub --once /harvest/request std_msgs/msg/String \
  "{data: 'farm01_plant_01_tomato_01'}"
```

Harvest route 상태 확인:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /harvest_route/status --once --field data
```

## 6. 정상 동작 확인 명령

### `/clock` 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /clock --once
```

### patrol 상태 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /patrol/status --once --field data
```

정상 예시:

```text
"state": "running"
"message": "Navigating to waypoint Home Pose (farm_01_home)."
```

### odom 위치 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /odom --once --field pose.pose.position
```

위치가 계속 변하고, `/patrol/status` 의 `distance_remaining_m` 값이 줄어들면 실제 주행 중입니다.

## 7. 문제 발생 시 체크 포인트

- `/patrol/start` 는 성공했는데 로봇이 안 움직이면 `/patrol/status` 의 `distance_remaining_m` 가 줄어드는지 먼저 확인
- 런치 로그에 `TF_OLD_DATA` 가 반복되면 기본 통합 런치 대신 위 저부하 분리 실행 사용
- 녹화나 카메라 bridge 부하가 크면 `use_camera_bridges:=false` 유지
- `/clock` 이 안 나오면 Gazebo 쪽이 정상 기동하지 않은 상태

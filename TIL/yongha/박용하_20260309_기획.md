## 오늘 진행한 내용 요약
금일은 **Gazebo 세팅 및 AI 모델의 실제 탑재/테스트를 수행하기보다는**,  
해당 작업을 안정적으로 진행하기 위한 **사전 계획 수립과 구조 설계**에 시간을 집중하였다.

특히 다음 항목들을 중심으로 검토하였다.

- **시뮬레이터 환경 방향성 정리**
  - Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic 조합을 기준 환경으로 설정하는 방향 검토
  - WSL 환경은 보조 용도로 활용하고, 실제 시뮬레이터 및 팀 공유 기준 환경은 네이티브 Ubuntu 기반이 더 적절한지 검토
  - Gazebo 환경을 실제로 구축할 경우 필요한 순서를 정리
    - Ubuntu 설치
    - ROS 2 Jazzy 설치
    - Gazebo Harmonic 설치
    - 카메라 토픽 확인
    - 이후 AI 추론 노드 연동

- **AI 모델 활용 방향 정리**
  - 현재 생성 완료된 **525 데이터 기반 ONNX 모델**을 우선 활용하는 방향이 적절한지 검토
  - 로봇 탑재 전 단계에서 가능한 테스트 방법 검토
    - test 셋 기반 성능 확인
    - 이미지/비디오 추론 테스트
    - ONNX 기반 로컬 추론 확인
    - 향후 ROS bag 기반 재생 테스트 가능성 검토

- **팀 공유를 위한 환경 구성 방식 검토**
  - 팀원들과 공통으로 사용할 때, 단순한 Python 가상환경만으로는 부족할 수 있음을 정리
  - 호스트 환경(ROS 2, Gazebo)은 공통 기준으로 맞추고,
    AI 추론 런타임만 별도 가상환경으로 관리하는 구조가 적절한지 검토
  - 향후 공유 가능한 형태:
    - 공통 repository
    - 모델 파일(`best.onnx`)
    - runtime requirements
    - setup script
    - launch 파일

- **FastAPI 등 추가 프레임워크 필요 여부 검토**
  - 현재 단계에서는 ROS2 토픽 기반 연동만으로도 충분하며,
    FastAPI 같은 웹 프레임워크는 필수 사항이 아님을 정리
  - 외부 웹 대시보드나 API 서버 연동이 필요할 경우에만 추후 도입 고려

## 오늘 기준으로 정리된 핵심 판단
1. **현재 생성된 525 데이터 기반 모델을 우선 활용하는 것이 적절함**
   - 이미 학습 및 ONNX export까지 완료된 상태이므로,
     새로운 데이터셋으로 다시 시작하기보다 현재 모델을 먼저 활용하는 것이 효율적임

2. **Gazebo/ROS2 환경은 AI보다 먼저 최소 동작 상태를 만드는 것이 필요함**
   - 모델 연동 이전에 카메라 토픽이 정상적으로 들어오는 환경을 우선 확보해야 함

3. **AI 추론용 가상환경은 필요하지만, ROS/Gazebo 전체를 대체할 수는 없음**
   - ROS 2와 Gazebo는 호스트 환경에 설치하고,
     ONNX Runtime 등 AI 추론 패키지만 별도 venv로 관리하는 것이 적절함

4. **현재 단계에서는 FastAPI보다 ROS2 노드 방식이 우선**
   - `/camera/image_raw` 구독 → 전처리 → ONNX 추론 → `/plant_diagnosis` publish 구조를 우선 구현하는 것이 맞음

# AgriBot Gazebo/RViz 실행 명령

이 문서는 절대 경로(`/home/ssafy/...`)에 의존하지 않고, 저장소를 어디에 clone 했든 그대로 실행할 수 있게 정리한 실행 절차입니다.

## 1. 공통 환경 변수

아래 명령은 각 터미널에서 먼저 실행합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
```

## 2. 최초 1회 또는 소스 변경 후 빌드

정적 맵을 다시 만들고 필요한 패키지만 빌드합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"

python3 src/agribot_navigation/agribot_navigation/generate_static_map.py \
  --output-prefix src/agribot_navigation/maps/farm_map \
  --boundary-yaml src/agribot_navigation/maps/farm_exploration_boundary.yaml

colcon build --packages-select agribot_description agribot_navigation agribot_bringup
source install/setup.bash
```

## 3. 기존 프로세스 정리

이전 Gazebo/Nav2/RViz 세션이 남아 있으면 먼저 정리합니다.

```bash
pkill -f 'ros2 launch agribot_bringup simulation.launch.py|ros2 launch agribot_description spawn_agribot.launch.py|ros2 launch agribot_navigation navigation.launch.py|gz sim|rviz2|controller_server|planner_server|bt_navigator|patrol_node|startup_map_tf_broadcaster|cmd_vel_watchdog|odom_tf_broadcaster|ros_gz_|map_server|amcl|lifecycle_manager|behavior_server|smoother_server|waypoint_follower|harvest_route_node' || true
```

## 4. 권장 실행 방식

기본 `simulation.launch.py`는 환경에 따라 `TF_OLD_DATA`가 재현될 수 있어서, 현재는 저부하 분리 실행을 권장합니다.

### 터미널 1: Gazebo + robot spawn

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_description spawn_agribot.launch.py \
  publish_map_to_odom_tf:=false \
  use_camera_bridges:=false
```

### 터미널 2: Navigation + RViz

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_navigation navigation.launch.py \
  use_sim_time:=true \
  use_rviz:=true \
  patrol_robot_pose_topic:=/odom
```

### 터미널 3: Patrol 시작

Navigation lifecycle 이 모두 active 가 된 뒤 실행합니다. 보통 5~10초 정도 기다리면 됩니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/start std_srvs/srv/Trigger "{}"
```

정상 응답 예시:

```text
success=True
message='Patrol start requested from the first waypoint.'
```

## 5. 다른 실행 방식

### 5-1. 통합 런치 1개로 빠르게 실행

가장 간단한 데모용 방식입니다. 다만 환경에 따라 `TF_OLD_DATA` 가 재현될 수 있어서 장시간 검증보다는 빠른 확인용으로 권장합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_bringup simulation.launch.py
```

### 5-2. RViz 없이 실행

Gazebo 와 Nav2 만 띄우고 RViz 는 생략하는 방식입니다. 원격 접속이나 저부하 실행에 적합합니다.

터미널 1:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_description spawn_agribot.launch.py \
  publish_map_to_odom_tf:=false \
  use_camera_bridges:=false
```

터미널 2:

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"

ros2 launch agribot_navigation navigation.launch.py \

  use_rviz:=false \
  patrol_robot_pose_topic:=/odom
```

### 5-3. Patrol 자동 시작

Navigation 이 뜨자마자 patrol 이 자동으로 시작되게 할 수 있습니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_navigation navigation.launch.py \
  use_sim_time:=true \
  use_rviz:=true \
  patrol_robot_pose_topic:=/odom \
  patrol_autostart:=true
```

### 5-4. Nav2 만 실행하고 patrol 노드는 빼기

수동 goal 테스트나 Nav2 자체만 확인할 때 사용합니다.

```bash
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"

source "/opt/ros/$ROS_DISTRO/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 launch agribot_navigation navigation.launch.py \
  use_sim_time:=true \
  use_rviz:=true \
  use_patrol:=false
```

### 5-5. Patrol 중지 / 재개

patrol 이 이미 실행 중일 때 수동으로 멈추거나 다시 이어갈 수 있습니다.

중지:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/stop std_srvs/srv/Trigger "{}"
```

재개:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 service call /patrol/resume std_srvs/srv/Trigger "{}"
```

### 5-6. 수동 harvest 요청

`navigation.launch.py` 에서 `use_harvest_route:=true` 가 기본이라, harvest coordinator 가 함께 떠 있으면 토마토 ID 를 직접 보내 수확 접근 시퀀스를 시작할 수 있습니다.

예시 tomato ID 는 `crop_instances.yaml` 기준으로 `farm01_plant_01_tomato_01` 형식입니다.

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic pub --once /harvest/request std_msgs/msg/String \
  "{data: 'farm01_plant_01_tomato_01'}"
```

Harvest route 상태 확인:

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /harvest_route/status --once --field data
```

## 6. 정상 동작 확인 명령

### `/clock` 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /clock --once
```

### patrol 상태 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /patrol/status --once --field data
```

정상 예시:

```text
"state": "running"
"message": "Navigating to waypoint Home Pose (farm_01_home)."
```

### odom 위치 확인

```bash
source "/opt/ros/${ROS_DISTRO:-jazzy}/setup.bash"
cd "$AGRIBOT_WS"
source install/setup.bash

ros2 topic echo /odom --once --field pose.pose.position
```

위치가 계속 변하고, `/patrol/status` 의 `distance_remaining_m` 값이 줄어들면 실제 주행 중입니다.

## 7. 문제 발생 시 체크 포인트

- `/patrol/start` 는 성공했는데 로봇이 안 움직이면 `/patrol/status` 의 `distance_remaining_m` 가 줄어드는지 먼저 확인
- 런치 로그에 `TF_OLD_DATA` 가 반복되면 기본 통합 런치 대신 위 저부하 분리 실행 사용
- 녹화나 카메라 bridge 부하가 크면 `use_camera_bridges:=false` 유지
- `/clock` 이 안 나오면 Gazebo 쪽이 정상 기동하지 않은 상태

# AgriBot 현재 진행 상황 및 명령어 모음

## 2026-03-23 기준

- 기본 `autonomous_mapping.launch.py`는 이제 frontier 우선이 아니라 `patrol-first`다.
- 기본값은 아래와 같다.
  - `use_frontier_explorer:=false`
  - `use_patrol:=true`
  - `patrol_autostart:=true`
  - `inspect_dwell_sec:=0.5`
- `use_frontier_explorer`와 `use_patrol`은 동시에 `true`로 둘 수 없다. 둘 다 켜면 launch가 즉시 실패한다.
- exploration boundary map server는 frontier 모드에서만 뜬다.
- 저발열 기본 방향은 다음과 같다.
  - camera bridge 비활성화 유지
  - SLAM scan throttling / map update 주기 완화
  - Nav2 BT / waypoint follower 루프 완화
  - collision monitor marker 시각화 비활성화
  - frontier fallback에서 recent-goal revisit 억제, recovery spin 축소, coverage fill 활성화

patrol 기반 sweep를 기본으로 쓴다. 로보락 초기 매핑처럼 통로를 따라 전진 위주로 지나가게 만드는 현재 권장 경로다.

```bash

source install/setup.bash
ros2 launch agribot_navigation autonomous_mapping.launch.py use_rviz:=false
```

### 2. RViz를 켠 시각화 디버그 실행


### 3. frontier fallback 매핑

온실처럼 정형적인 환경에서는 기본 권장 모드가 아니지만, 일반 frontier 탐사가 필요하면 patrol을 끄고 frontier만 켠다.

```bash

source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch agribot_navigation autonomous_mapping.launch.py \
  use_frontier_explorer:=true \
  use_patrol:=false \
  use_boundary_map:=true \
  use_rviz:=false
```

## 현재 발열/연산량 해석

- `autonomous_mapping.launch.py`를 브랜치 초기 시점과 비교하면, 현재 기본 경로는 대체로 더 가볍다.
- 이유는 다음이 더 크게 작용한다.
  - camera/depth bridge가 기본 off
  - SLAM Toolbox가 더 저주파 / 저해상도
  - Nav2 controller, planner, costmap 주기가 훨씬 낮음
- 반대로 지금이 더 무거운 부분도 있다.
  - EKF, collision monitor, boundary map server, richer frontier supervisor가 추가됨
- 하지만 기본 경로를 patrol-first로 바꾸면 frontier 특유의 goal 재선정, recovery spin, boundary follow 루프가 빠지기 때문에 체감 발열은 더 낮아지는 쪽이 맞다.
- 가장 낮은 발열은 여전히 `use_rviz:=false`일 때다. Gazebo 렌더링과 RViz가 체감 발열에 미치는 영향이 크다.

## 주의사항

- patrol은 구조화된 통로 환경에서 기본 권장 모드다.
- frontier는 fallback으로만 쓰고, 쓸 때도 `use_patrol:=false`로 분리해서 실행한다.
- `use_boundary_map`은 frontier 모드용 옵션이다. patrol 기본 경로에서는 boundary map server가 뜨지 않는다.
- frontier 상태가 `Waiting for boundary map`에 머무르던 문제는 transient-local QoS 구독으로 보완했다.

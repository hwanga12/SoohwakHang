# 프론트엔드 켜놓은 후 시연용 명령어 모음

이 문서는 발표 직전에 팀원 누구나 같은 순서로 실행할 수 있게 정리한 실행 문서입니다.

핵심 원칙은 2가지입니다.

- backend와 ROS가 반드시 같은 `AGRIBOT_RUNTIME_DIR`를 본다.
- 병해 모델을 쓸 때는 팀 공통 경로 `artifacts/models/tomato_disease/v1/best.pt` 또는 `AGRIBOT_TOMATO_MODEL_PATH`를 사용한다.

## 1. 공통 환경

모든 터미널에서 먼저 아래를 맞춥니다.

```bash
cd /path/to/S14P21A602
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"
export AGRIBOT_RUNTIME_DIR="${AGRIBOT_RUNTIME_DIR:-/tmp/agribot_runtime}"
export CUDA_VISIBLE_DEVICES="${CUDA_VISIBLE_DEVICES:-0}"
```

같은 값을 모든 터미널에 반복해서 맞출 때는 아래 스크립트를 먼저 실행합니다.

```bash
source <(./scripts/operator_runtime_health.sh --print-env)
./scripts/operator_runtime_health.sh --reset-runtime
```

병해 모델 가중치를 기본 위치에 두는 경우:

```bash
ls "$REPO_ROOT/artifacts/models/tomato_disease/v1/best.pt"
```

가중치를 다른 곳에 둔 경우:

```bash
export AGRIBOT_TOMATO_MODEL_PATH="/path/to/best.pt"
```

## 2. 준비 기준

아래는 "항상 다시 해야 하는 것"이 아니라, **필요할 때만 다시 하는 준비 작업**입니다.

### 2-1. frontend 의존성 설치

`frontend/package-lock.json`이 바뀌었거나, `node_modules`가 없거나 꼬였을 때만 다시 실행합니다.

```bash
cd "$REPO_ROOT/frontend"
npm ci
```

의존성을 실제로 추가/변경하는 사람이 아니라면 `npm install`보다 `npm ci`를 우선 사용합니다.

### 2-2. backend 가상환경 준비

`backend/requirements.txt`가 바뀌었거나 `.venv`가 없을 때만 다시 실행합니다.

```bash
cd "$REPO_ROOT/backend"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 2-3. ROS 워크스페이스 빌드

`agribot_ws/src` 아래 코드가 바뀌었으면 다시 빌드합니다. 이번처럼 launch, navigation, description, bringup 파일이 바뀐 merge 뒤에는 다시 빌드하는 것이 맞습니다.

```bash
cd "$AGRIBOT_WS"
source "/opt/ros/$ROS_DISTRO/setup.bash"
colcon build --symlink-install
```

## 3. 시연 시작 전 초기화

이전 runtime 파일이 남아 있으면 이전 수확/병해 상태가 그대로 보여서 헷갈릴 수 있습니다.

```bash
rm -rf "$AGRIBOT_RUNTIME_DIR"
mkdir -p "$AGRIBOT_RUNTIME_DIR"
echo "$AGRIBOT_RUNTIME_DIR"
```

프론트는 시연용으로 `npm run dev`를 쓰므로 `npm run build`나 `frontend/dist` 삭제가 기본 필수는 아닙니다.

- `npm run build`는 배포용 번들 생성 확인이나 프론트 번들 오류 점검이 필요할 때만 실행합니다.
- `frontend/dist` 삭제는 `npm run preview`나 정적 배포 파일을 다시 검증할 때, 또는 이전 산출물이 남아 헷갈릴 때만 합니다.
- ROS 쪽 `build/`, `install/`, `log/` 삭제는 기본 절차가 아니고, colcon 캐시가 꼬였거나 오래된 설치 결과가 계속 남는다고 의심될 때만 합니다.

## 4. 실행 순서

### 터미널 1. backend 실행

```bash
./scripts/backend_up.sh
```

### 터미널 2. frontend 실행

```bash
./scripts/frontend_up.sh
```

브라우저:

- 메인 조작판: `http://localhost:5173/`
- 식물 화면: `http://localhost:5173/plants`
- 수확 화면: `http://localhost:5173/harvest`
- 알림 화면: `http://localhost:5173/alerts`

### 터미널 3. ROS 시뮬레이션 실행

`simulation.launch.py`가 Gazebo, navigation, mission bridge executor, runtime snapshot exporter, perception launch까지 함께 올립니다.

```bash
export CUDA_VISIBLE_DEVICES="$CUDA_VISIBLE_DEVICES"
./scripts/agribot_launch.sh agribot_bringup simulation.launch.py use_iot:=false
```

### 터미널 4. mission manager 실행

병해 관측 우선순위와 미션 반영 흐름까지 보려면 함께 띄웁니다.

```bash
./scripts/mission_manager_up.sh
```

### 터미널 5. harvest action server 실행

수확 phase, 바구니 적재량, 마지막 수확 fruit id를 프론트와 backend가 읽게 하려면 꼭 필요합니다.

```bash
./scripts/harvest_action_server_up.sh
```

## 5. 실행 확인 명령

### 5-1. 필요한 ROS 노드 확인

```bash
source "/opt/ros/$ROS_DISTRO/setup.bash"
source "$AGRIBOT_WS/install/setup.bash"
ros2 node list | egrep 'thin_inference_node|mission_bridge_executor|mission_manager|patrol_node|harvest_route_node|harvest_action_server'
```

backend, frontend, ROS node, runtime 파일, `AGRIBOT_RUNTIME_DIR` 불일치를 한 번에 보려면 아래도 함께 실행합니다.

```bash
./scripts/operator_runtime_health.sh
```

### 5-2. runtime 파일 확인

```bash
find "$AGRIBOT_RUNTIME_DIR" -maxdepth 2 -type f | sort
```

### 5-3. backend 기본 API 확인

```bash
curl -s http://localhost:8000/api/v1/alerts | jq
curl -s http://localhost:8000/api/v1/plants | jq
curl -s http://localhost:8000/api/v1/harvests/stats | jq
curl -s http://localhost:8000/api/v1/harvests | jq
```

## 6. 발표용 시나리오

### 6-1. 병해 발견 시연

브라우저:

1. `/plants` 또는 `/alerts`에서 병해 알림 카드와 실제 이미지가 뜨는지 확인합니다.
2. `/plants`에서 식물을 눌러 최근 진단 결과와 사진을 확인합니다.

같이 보면 좋은 명령:

```bash
curl -s http://localhost:8000/api/v1/alerts | jq '.data[:3]'
curl -s http://localhost:8000/api/v1/plants/farm01_plant_06/observations | jq
```

이미지 URL이 보이면 아래도 확인합니다.

```bash
curl -I "http://localhost:8000/api/v1/media/$(curl -s http://localhost:8000/api/v1/plants/farm01_plant_06/observations | jq -r '.data[0].asset_id')"
```

### 6-2. 메인 화면에서 진단하기 시연

브라우저:

1. `/`에서 식물을 클릭합니다.
2. 모달에서 `진단하기`를 누릅니다.
3. 버튼 문구와 상태가 `진단 이동 준비 -> 이동 중 -> 도착 완료`로 바뀌는지 봅니다.

같이 보면 좋은 명령:

```bash
curl -s http://localhost:8000/api/v1/robot/commands/latest | jq
cat "$AGRIBOT_RUNTIME_DIR/robot_manual_command.json" | jq
cat "$AGRIBOT_RUNTIME_DIR/robot_manual_command_status.json" | jq
```

### 6-3. 메인 화면에서 수확하기 시연

브라우저:

1. `/`에서 수확 가능한 식물을 클릭합니다.
2. 식물 모달을 닫지 말고 `수확하기`를 누릅니다.
3. 모달 안에서 `접근 중 -> 토마토 집는 중 -> 등 바구니에 적재 중 -> 수확 및 적재 완료` 흐름이 보이는지 확인합니다.
4. 같은 식물이 맵에서 `handled` 상태로 바뀌는지 확인합니다.

같이 보면 좋은 명령:

```bash
cat "$AGRIBOT_RUNTIME_DIR/robot_mission_request.json" | jq
MISSION_ID="$(jq -r '.mission_id' "$AGRIBOT_RUNTIME_DIR/robot_mission_request.json")"
curl -s "http://localhost:8000/api/v1/missions/$MISSION_ID" | jq
curl -s http://localhost:8000/api/v1/harvests/stats | jq
curl -s http://localhost:8000/api/v1/harvests | jq
```

수확 runtime 파일을 직접 보면 더 명확합니다.

```bash
cat "$AGRIBOT_RUNTIME_DIR/harvest_action_status.json" | jq
cat "$AGRIBOT_RUNTIME_DIR/harvest_basket_state.json" | jq
cat "$AGRIBOT_RUNTIME_DIR/harvest_latest_event.json" | jq
```

### 6-4. 수확 화면 시연

브라우저:

1. `/harvest`로 이동합니다.
2. 상단 hero에서 현재 phase, 바구니 적재량, 마지막 수확 fruit id가 실제 값으로 보이는지 확인합니다.
3. 아래 배치 카드에서 현재 수확 대상, phase, 적재 개수가 보이는지 확인합니다.

같이 보면 좋은 명령:

```bash
curl -s http://localhost:8000/api/v1/harvests/stats | jq '.data | {basket_count, remaining_ready_count, last_harvested_fruit_id, current_phase, active_mission_id}'
curl -s http://localhost:8000/api/v1/harvests | jq '.data[:5]'
```

### 6-5. 패트롤 버튼 시연

브라우저:

1. `/` 오른쪽 조작판에서 `패트롤로 병 진단` 또는 `패트롤로 전체 수확`을 누릅니다.
2. accepted만으로 성공 처리하지 않고, 상태 polling 이후에만 결과가 바뀌는지 확인합니다.

같이 보면 좋은 명령:

```bash
cat "$AGRIBOT_RUNTIME_DIR/robot_mission_request.json" | jq
MISSION_ID="$(jq -r '.mission_id' "$AGRIBOT_RUNTIME_DIR/robot_mission_request.json")"
curl -s "http://localhost:8000/api/v1/missions/$MISSION_ID" | jq
cat "$AGRIBOT_RUNTIME_DIR/robot_mission_status.json" | jq
```

## 7. 발표 중 빠르게 보는 요약 명령

```bash
watch -n 1 "curl -s http://localhost:8000/api/v1/harvests/stats | jq '.data | {basket_count, remaining_ready_count, last_harvested_fruit_id, mission_status, current_phase}'"
```

```bash
watch -n 1 "curl -s http://localhost:8000/api/v1/alerts | jq '.data[:3]'"
```

```bash
watch -n 1 "curl -s http://localhost:8000/api/v1/missions/$(jq -r '.mission_id' \"$AGRIBOT_RUNTIME_DIR/robot_mission_request.json\" 2>/dev/null) | jq '.data'"
```

## 8. 종료 명령

ROS 시뮬레이션을 정리할 때:

```bash
cd "$REPO_ROOT"
./scripts/cleanup_sim_processes.sh
```

backend / frontend는 각 터미널에서 `Ctrl+C`로 종료합니다.

## 2026-03-23 기준

- 기본 자율 매핑 전략은 이제 `mapping_strategy:=sweep_hybrid`다.
- 기본 정적 맵, 수확 patrol metadata, crop catalog의 기준 zone은 이제 `farm_01`이다.
- `sweep_hybrid`의 동작 순서는 아래와 같다.
  - patrol sweep 자동 시작
  - patrol 완료
  - frontier hole-fill 자동 요청
- 기본 목표는 로보락 스타일에 가까운 전진 위주 sweep를 유지하면서, 노트북 발열과 연산량을 크게 늘리지 않는 것이다.
- 이번 기준선의 핵심 변경은 아래다.
  - patrol 주행의 주권 강화
  - non-observe waypoint 연속 구간을 `NavigateThroughPoses`로 배치 주행
  - mapping profile에서 `allow_unknown: true`
  - BT의 180도 recovery spin과 과도한 retry 축소
  - SLAM map update를 `4.0s -> 2.0s`로 낮춰 반응성 회복

## 현재 발열/연산량 해석

- `sweep_hybrid`는 frontier를 기본 주행 엔진으로 쓰지 않는다.
- 그래서 아래 비용이 기본 경로에서 줄어든다.
  - 잦은 frontier goal 재선정
  - 큰 recovery spin
  - repeated bootstrap / boundary-follow decision loop
- 반면 SLAM 반응성을 위해 `map_update_interval`은 `2.0s`로 낮췄다.
- 이 증가분은 patrol-first 배치 주행과 reduced recovery가 상쇄하는 쪽이라, 전체적으로는 큰 발열 증가 없이 더 자연스러운 sweep가 나오도록 설계했다.
- 가장 낮은 발열은 여전히 `use_rviz:=false`일 때다.

## 운영 메모

- `mapping_strategy:=sweep_hybrid`에서는 patrol과 frontier 노드가 함께 올라오지만, frontier는 patrol 완료 전까지 auto-start되지 않는다.
- patrol은 연속 non-observe 구간을 `NavigateThroughPoses`로 묶어 stop-and-go를 줄인다.
- inspect waypoint는 짧은 dwell만 유지한다.
- 매핑용 planner는 `allow_unknown: true`라 초기 미지 공간에서도 patrol path가 더 부드럽게 열린다.
- recovery는 Nav2 BT와 상위 전략 모두에서 짧은 회전 위주로 줄였고, 큰 180도 spin 반복은 피하도록 조정했다.

## RViz 화면 요소 의미

현재 `mapping.rviz` 화면은 여러 display가 겹쳐서 보인다. 헷갈리기 쉬운 요소를 아래처럼 보면 된다.

### 1. 하얀색 바닥

- 주로 `/map`을 그리는 `Map` display다.
- 이미 SLAM이 "여기는 지나갈 수 있는 바닥"이라고 판단한 free space가 밝게 보인다.
- 완전히 빈 배경이 아니라, 로봇이 스캔해서 확보한 2D 지도 영역이라고 보면 된다.

### 2. 회색 격자 바닥

- 실제 지도 데이터가 아니라 `Grid` display다.
- RViz 기준 좌표계를 보기 쉽게 깔아둔 배경선이다.
- 지도나 장애물 의미는 없다.

### 3. 빨간 선

- 문서에서 가장 헷갈리기 쉬운 부분이다.
- RViz를 켜자마자 보이는 빨간색이 항상 `Global Plan`은 아니다.
- 구분은 아래처럼 하면 된다.
  - 얇고 한 줄로 이어진 빨간 선: `Global Plan`일 가능성이 크다.
  - 띠처럼 두껍거나 격자/셀처럼 깔린 빨간 표시: `Costmap`일 가능성이 크다.
- `Global Plan`일 때:
  - 토픽은 `/plan`
  - 전역 planner가 계산한 "멀리 보면 이렇게 가라"는 경로다.
  - 보통 더 길고, 통로 전체를 관통하는 큰 경로처럼 보인다.
- startup 직후 아직 목표 경로가 없는데도 빨간색이 보인다면, 그건 대개 경로선이 아니라 costmap 쪽 표시다.

### 4. 파란 선

- 기본적으로 `Local Plan`이다.
- 토픽은 `/local_plan`이고, controller가 현재 순간에 실제로 따라가려는 짧은 경로다.
- 빨간 전역 경로 위를 완전히 그대로 따르기보다, 현재 로봇 자세와 주변 장애물을 반영해서 더 짧고 자주 바뀐다.

### 5. 로봇 주변에서 움직이는 빨간 점선/붉은 띠처럼 보이는 것

- 대체로 `Local Costmap` 영향이다.
- 로봇 중심으로 함께 움직이는 근거리 회피용 비용 지도이며, 토픽은 `/local_costmap/costmap`이다.
- 의미는 "이 근처는 가까운 장애물 때문에 피해야 하거나, 들어가면 비용이 매우 커지는 구역"이다.
- 실제 바닥에 그려진 선이 아니라, 로봇 주변 안전 판단용 격자창이라고 보면 된다.
- 즉, 물리적 벽 그 자체를 빨간 선으로 직접 그린 것이라기보다, 벽/장애물 때문에 Nav2가 위험하다고 판단한 셀을 붉게 보여주는 것이다.

### 6. 로봇이 지나가는 쪽에 겹쳐 보이는 빨간색/파란색 선

- 빨간색은 경우가 두 가지다.
  - 얇은 선이면 전역 planner의 의도 경로
  - 셀/띠처럼 깔리면 costmap의 고비용 구역
- 파란색은 대체로 local controller의 즉시 추종 경로이거나 costmap 계열 표시다.
- 그래서 로봇이 움직일 때
  - 빨간 얇은 선과 파란 선이 거의 겹치면: 전역/지역 경로가 잘 일치하는 상태
  - 로봇 주변에 빨간 띠가 생기면: 근처 장애물/벽 때문에 local 회피 비용이 커진 상태
- 정리하면
  - 빨간 얇은 선: 어디로 갈지
  - 파란 얇은 선: 지금 당장 어떻게 갈지
  - 빨간 띠/셀: 피해야 할 고비용 구역

### 7. 흰 점이나 밝은 점들

- `LaserScan` display다.
- 토픽은 `/agribot/lidar`이고, LiDAR가 현재 감지한 벽/장애물 반사점이다.
- 로봇 주변에서 실시간으로 반짝이며 바뀌는 점 구름처럼 보인다.

### 8. 로봇 자체

- `RobotModel` display다.
- `/robot_description` 기준으로 URDF/SDF 모델을 RViz에 그린 것이다.
- 실제 주행 판단 데이터라기보다, 현재 TF 위치에 맞춰 로봇 외형을 보여주는 시각화다.

## 2026-03-25 초보자용: `/robot` 화면과 Gazebo를 같이 보며 실제 클릭 이동 확인하기

현재 기준으로 `/robot` 화면은 아래 3가지를 실제로 할 수 있다.

1. 식물/급수 포인트를 선택해서 semantic asset 정보를 본다.
2. 빈 지도 공간을 클릭해 `navigate_to_pose` 이동 목표를 보낸다.
3. `빠른 구역 이동` 버튼으로 `/zones`의 대표 좌표를 기준으로 이동 요청을 보낸다.

즉, 이제는 **RViz의 `2D Goal Pose`에 의존하지 않아도 `/robot` 화면만으로 클릭 이동 시연이 가능하다.**

### 1. 저장소 진입 + 공통 변수 준비

이 단계부터 시작할 때는 반드시 실제 `S14P21A602` 저장소 내부로 먼저 들어간다.

`~/SSAFY`처럼 저장소 바깥 디렉터리에서 바로 `git rev-parse --show-toplevel`을 실행하면 `REPO_ROOT`가 비거나 명령 자체가 실패할 수 있다.

```bash
cd /path/to/S14P21A602   # 예: cd ~/SSAFY/S14P21A602
export REPO_ROOT="$(git rev-parse --show-toplevel)"
export AGRIBOT_WS="$REPO_ROOT/agribot_ws"
export ROS_DISTRO="${ROS_DISTRO:-jazzy}"
```

### 2. 처음이거나 오래됐으면 한 번 빌드

- 로봇 화면: `http://localhost:5173/robot`

### 6. 가장 쉬운 시연: `/robot` 화면에서 빈 공간 클릭 이동

브라우저의 `/robot` 화면에서 아래 순서로 한다.

1. 먼저 지도를 한 번 보고, 식물/급수 포인트는 선택용이라는 점을 기억한다.
2. 식물 아이콘이 아닌 **빈 지도 공간**을 클릭한다.
3. 지도 위에 `선택 좌표` 마커가 뜨고, 아래에 `이 좌표로 이동 / 취소` 시트가 나온다.
4. `이 좌표로 이동`을 누른다.
5. 우측 `이동 명령 상태` 카드가 `pending -> running -> succeeded/failed`로 바뀌는지 본다.
6. Gazebo 안 로봇이 실제로 움직이는지 같이 확인한다.

중요한 점:

- 빈 공간 클릭만 이동 목표다.
- 식물/급수 포인트 클릭은 계속 선택만 수행한다.
- 벽이나 장애물처럼 보이는 칸을 클릭하면 이동 목표로 잡히지 않을 수 있다.

### 7. 빠른 구역 이동 시연

빈 공간 클릭 대신 `빠른 구역 이동` 버튼으로도 시연할 수 있다.

`/robot` 화면 오른쪽 패널에서 아래 중 하나를 누른다.

- `farm_01_west`
- `farm_01_center`
- `farm_01_east`

이 버튼들은 지금은 stub가 아니라 `/api/v1/zones`가 내려주는 `representative_pose`를 기준으로 `move_to_zone` 요청을 보낸다.

즉, 초보 시연자는 **버튼 하나만 눌러도 구역 이동 시연이 가능하다.**

### 8. `/robot` 화면에서 무엇을 보면 되나

아래 항목을 같이 보면 된다.

- 지도 위 로봇 아이콘 위치
- `현재 위치`
- `현재 구역`
- `다음 목표`
- `이동 명령 상태`

현재 프론트는 `/robot/pose`와 `/robot/commands/latest`를 주기적으로 다시 읽기 때문에, Gazebo 안 로봇이 움직인 뒤 몇 초 정도 지나면 웹 화면도 상태가 같이 바뀌어야 정상이다.

### 9. RViz의 `2D Goal Pose`는 이제 보조 확인용

이제 기본 시연은 `/robot` 화면만으로 가능하지만, 필요하면 RViz에서도 추가 확인을 할 수 있다.

보조 확인 순서:

1. RViz 상단 툴바에서 `2D Goal Pose` 클릭
2. 지도 위 원하는 위치와 방향 지정
3. Gazebo에서 이동 확인
4. `/robot` 화면 위치가 따라오는지 확인

즉, RViz는 이제 **필수 시연 도구가 아니라 보조 검증 도구**에 가깝다.

### 10. 순찰 시작으로 비교 확인하고 싶다면

클릭 이동과 별개로 기존 patrol 흐름도 같이 비교할 수 있다.

터미널 4를 열고 아래 명령을 실행한다.

```bash
cd "$AGRIBOT_WS"
source "/opt/ros/$ROS_DISTRO/setup.bash"
source install/setup.bash
ros2 service call /patrol/start std_srvs/srv/Trigger "{}"
```

이 경우에도 Gazebo에서 로봇이 움직이고, `/robot` 화면의 현재 위치와 상태 카드가 바뀌는지 같이 보면 된다.

### 11. 잘 안 되면 먼저 볼 것

- `http://localhost:8000/docs`가 열리는지
- `http://localhost:5173/robot`이 열리는지
- Gazebo와 RViz가 모두 떴는지
- 현재 위치가 실제 `S14P21A602` 저장소 내부인지
- `echo "$REPO_ROOT"` 결과가 비어 있지 않고 `.../S14P21A602`로 끝나는지
- `/robot`에서 식물 아이콘이 아니라 **빈 지도 공간**을 클릭했는지
- `이 좌표로 이동` 또는 `빠른 구역 이동` 버튼을 실제로 눌렀는지
- 우측 `이동 명령 상태` 카드가 `pending` 이상으로 바뀌는지

상태 카드가 계속 `idle`이면 backend 또는 executor가 아직 명령 파일/상태 파일을 주고받지 못하는 경우일 수 있다.

`cd "$REPO_ROOT/frontend"`가 `/frontend`로 바뀌거나 `npm`이 엉뚱한 상위 폴더의 `package.json`을 찾으면, 거의 항상 1번 단계에서 저장소 진입 또는 `REPO_ROOT` 설정이 빠진 경우다.

### 12. 마지막 체크 포인트

정상이라면 아래 순서가 눈에 보여야 한다.

1. `/robot`에서 목표 선택
2. 확인 버튼 클릭
3. 상태 카드 `pending`
4. 상태 카드 `running`
5. Gazebo 이동

이 순서가 보이면, 현재 `/robot` 화면 기준 클릭 이동 시연은 정상이라고 보면 된다.
